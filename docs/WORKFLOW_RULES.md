# StoryFrame-Studio AI 협업 및 작업 규칙 (SOP)

이 문서는 오케스트레이터(Antigravity)와 백그라운드 에이전트, 그리고 사용자가 협업하여 프로젝트를 개발할 때 반드시 지켜야 하는 핵심 규칙입니다.

## 1. 작업 전 컨텍스트 동기화 및 실행 허가 (Permission)
- 모든 백그라운드 에이전트는 코딩을 시작하기 전, 반드시 기획서(`PLAN.md`, `PRD.md`)를 읽어야 합니다.
- **[4대 전담 에이전트 및 참고서 필독]** 개발은 아래 4명의 전문 에이전트(Agent)로 역할을 분담하며, 오케스트레이터는 호출 시 각자 전담 기술 문서(`docs/references/`)를 반드시 정독하도록 지시해야 합니다:
  1. **UI 에이전트**: React, Tailwind 화면 렌더링 담당 👉 `frontend_ui_research.md` 필독
  2. **로직 에이전트**: Zustand 상태 관리, IPC 통신 담당 👉 `frontend_logic_research.md` 필독
  3. **코어 에이전트**: Tauri 뼈대, Rust 파일 시스템 제어 담당 👉 `backend_core_research.md` 필독
  4. **미디어 에이전트**: FFmpeg 제어, 파형 추출, 내보내기 담당 👉 `media_engine_research.md` 필독
- **[스마트 실행 허가]** 사용자가 "Phase 5 시작해"처럼 명시적으로 작업 지시를 내렸다면, 굳이 "시작할까요?"라고 **중복해서 묻지 말고 즉시 백그라운드 에이전트를 투입해 작업을 쾌속 진행**하십시오. 단, 지시받지 않은 대규모 코드 삭제/롤백 등 위험한 독단적 행동을 할 때만 허락을 구하세요.

## 2. 세션 교체 (킬 & 인보크) 및 상태 로깅
- 에이전트는 하나의 굵직한 기능(Feature)이나 단계(Phase)를 완료하면, 퇴근하기 전에 반드시 `project_state.json`을 최신 상태로 업데이트하여 인수인계 기록(Log)을 남깁니다.
- 오케스트레이터는 토큰 과부하와 환각(Hallucination) 방지를 위해, 작업이 끝난 에이전트 세션을 즉각 종료(Kill)하고, 다음 작업 시 새로운 쌩쌩한 세션(Invoke)을 생성합니다.

## 3. 교차 검증 및 Claude 4.6 Sonnet 리팩토링 (토큰 절약)
- 기능 구현(Make it work)이 완료되어 하나의 Phase가 끝나면, 오케스트레이터는 **반드시 `PLAN.md`와 실제 구현된 코드를 대조하여 누락된 디테일이나 오류가 없는지 교차 검증(Cross-validation)**을 수행합니다.
- **[자동 프롬프트 생성]** 교차 검증을 마친 후, 사용자에게 **'Claude 4.6 Sonnet 전용 리팩토링 프롬프트'**를 자동으로 작성하여 제공합니다. (단, 프로젝트 폴더 내에 마크다운 파일로 저장하지 말고, 채팅창 출력이나 Antigravity 아티팩트(Artifact)로만 제공해야 합니다.)
- **[토큰 낭비 방지 (매우 중요)]** Claude 모델의 쿼터(한도) 보호를 위해, 리팩토링 프롬프트에는 **"전체 폴더 스캔 금지. 반드시 지정된 타겟 파일(2~3개)만 읽고 수정할 것"**이라는 제한 조건을 반드시 명시해야 합니다.
- **[외부 작업 및 반영]** 사용자가 리팩토링된 코드를 오케스트레이터에게 전달하면, 오케스트레이터가 이를 로컬 프로젝트에 적용(Apply)합니다.

## 4. Git 버전 관리 및 백업
- 리팩토링 및 코드 반영이 모두 완료되어 하나의 Phase가 흠잡을 데 없이 마무리되면, 오케스트레이터는 **반드시 로컬 저장(Commit)과 사이트 업로드(Push)를 한 세트로 묶어서 한 방에 처리(자동 실행)**하여 버전을 영구 백업합니다. (따로 분리해서 묻거나 헷갈리게 하지 않습니다.)
- 커밋 메시지는 `feat:`, `fix:`, `chore:`, `refactor:` 등의 글로벌 표준(Conventional Commits)을 따릅니다.
